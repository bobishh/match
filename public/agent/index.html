Match agent guide

Local-first job search board. Vacancy cards, CVs, cover letters, notes, and file references stay together. No account. No backend. No organization ceremony.

Core ruleFlat cards.
Visible state.

Agent commands mutate the same board the user sees.

Open Match locally

  1. Install dependencies in match/ with npm install.
  2. Build the browser sync runtime with npm run build:iroh.
  3. Start the app with npm run dev.
  4. Open http://127.0.0.1:5173/. Agent documentation is at http://127.0.0.1:5173/agent/.

For a production static build, run npm run build and serve dist/. The workspace is stored in the browser's IndexedDB.

Pipeline

Cards move through five statuses:

leadappliedinterviewrejectedoffer

Card fields

  • company — company name.
  • role — vacancy title.
  • url — source vacancy URL.
  • location and workMode — location and remote/hybrid/onsite mode.
  • status — pipeline status.
  • priority — p0, p1, p2, or p3.
  • fitScore — optional number from 0 to 10.
  • notes, description, and sourceText — plain text context.

Attached documents

Each document belongs directly to one card. Kinds: cv, cover_letter, note, and attachment. Formats: markdown, html, pdf, and path. Local file references use an absolute path and stay local.

WebMCP tools

When the Match app is open in a browser that exposes WebMCP through document.modelContext or navigator.modelContext, it registers these tools. The tools mutate the same visible workspace as the UI:

list_leads

Read cards. Optional status and search filters.

create_lead

Create one flat card. Required company, role, status.

move_lead

Move a card by leadId and status.

add_document

Attach a document by leadId, kind, title, and format.

export_workspace

Download the workspace as a .match bundle and JSON data.

Do not send organization objects, nested CRDT payloads, or unknown fields. Duplicate vacancy URLs, or the same company plus role, return a duplicate result instead of creating a second card.

Storage and sync

Cards and documents live in IndexedDB as an Automerge document. The sync dialog starts the experimental browser iroh/WASM transport. QR pairing opens a /pair#... HTTPS invite carrying an endpoint and a random authorization secret; only the matching secret can merge another device's workspace.

Export shape

The JSON export contains two top-level arrays: leads and documents. A document references its card through leadId. The portable .match bundle also contains the manifest and Automerge bytes.
