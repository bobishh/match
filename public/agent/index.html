Match agent guide

Operate the same local-first workspace the user sees. Read stable IDs first, then mutate typed entities through WebMCP commands.

Working model

A device owns a local catalog of independent workspaces. Each workspace is one Automerge document containing its board schema, items, document templates, history, and collaboration metadata. WebMCP commands target the current workspace shown in Match; creating a workspace makes it current.

  • Every entity has a stable UUID. Titles are display text and may change.
  • placement.parentId links a column to its board, a task to a column or parent task, and an artifact to its task. placement.rank orders siblings.
  • Soft deletion applies to entities. Deleting a column hides its descendant tasks; restoring the column reveals them with their relationships intact.
  • Archive is a normal workspace column. Trash contains explicitly deleted entities. Broken or cyclic ancestry appears through placement issues.
  • Job search is one preset. Its lead vocabulary and pipeline are workspace-specific, never kernel assumptions.

Safe agent workflow

  1. Call list_workspaces to inspect the local catalog. The user controls which existing workspace is current.
  2. Call get_workspace_settings. Resolve board, column, field, option, and template IDs from its result.
  3. Read items with list_tasks or inspect one typed entity with get_entity.
  4. Use generic mutation tools. Put custom values under stable field IDs, not field titles.
  5. Re-read visible state after mutations. Treat returned IDs and CRDT heads as authoritative.

Complete workspace settings

get_workspace_settings returns settings plus heads. Settings contain formatVersion, workspace.title, the board title and item name, ordered columns, typed fields and select options, and documentTemplates. Templates belong to that workspace and describe documents generated for its items; they have no fixed CV/cover-letter kind enum.

To change the complete configuration, edit the returned object and call apply_workspace_settings with those heads as expectedHeads. The apply is one validated CRDT transaction. Omitted columns, fields, and templates are soft-deleted. Existing descendants and field values remain stored.

Keep IDs returned by Match when editing. Omit an ID only when adding a column, field, field option, or document template. A field's valueType cannot change in place.

Mutation rules

  • Unknown fields are rejected without mutation. Send command inputs, never raw Automerge objects or changes.
  • Keep returned IDs. Names are editable labels and cannot identify an entity safely.
  • Use expectedHeads for settings writes. On a conflict, re-read settings, reapply the intended edit, and submit the new heads.
  • Use restore_and_move when an entity's former parent is deleted or missing. Do not repair ancestry by recreating the entity.
  • Inspect list_placement_issues only for recovery. Normal parent/child relationships need no repair.

Job-search compatibility tools

The default Job search preset also exposes legacy adapters: list_leads, create_lead, move_lead, list_templates, get_generation_context, record_pdf_artifact, add_document, and export_workspace. Use generic tools for workspace-independent automation. Legacy status names and lead fields only describe that preset.

Sync, identity, and storage

  • Share workspaces: Sync opens with the current workspace selected. Select one or more existing workspaces, then generate one invitation for that fixed set. The recipient keeps a separate person and device identity.
  • Sync all / Add my device: enrolls another device under the same personal identity and shares the personal workspace catalog after mutual code approval.
  • Automerge changes sync incrementally while peer sessions are live. Workspace snapshots and trust state persist in IndexedDB.
  • A .match export carries workspace data, Automerge history, and public proofs. It excludes private signing keys, the personal root, and pairing secrets.

Run locally

Install dependencies with npm install, build the browser transport with npm run build:iroh, then start Vite with npm run dev. Workspaces remain in that browser profile's IndexedDB. Production builds use npm run build.
